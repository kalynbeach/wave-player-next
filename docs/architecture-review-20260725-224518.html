Problem

React owns library loading, scan ordering, playback failure policy, preset persistence, and cross-runtime state; the settled application seam has weak locality.

Solution

Move those workflows behind one deep application module; leave React as the subscription and lifecycle adapter required by the architecture.

Benefits

  • • locality: ordering lives together
  • • leverage: one workflow interface
  • • tests avoid React rendering
  • • failures become observable outcomes
Deletion test: remove this behavior from ConnectedPlayer and the same complexity reappears across PlayerCard, HTTP calls, and controller callers. A deep module would concentrate it.
Restores the settled decision: application orchestration belongs in src/app/; React stays thin.

Problem

The two registries repeat lookup invariants while interaction, labels, keyboard behavior, and scene selection leak into session and React callers.

Solution

Deepen the existing built-in scene seam so scene knowledge has locality, while preserving explicit scene controls and browser renderer adapters.

Benefits

  • • locality: scene knowledge concentrates
  • • fewer registry navigation hops
  • • callers lose scene switches
  • • tests target scene behavior
Deletion test: deleting VisualizationSceneRegistry moves little implementation; it is shallow. Deleting the core registry spreads validation. Deepen the earned seam and collapse the shallow chain.
Constraint from the decision log: no public scene plugins and no schema-driven control framework. Leverage is bounded until a third built-in Scene exists.

Top recommendation

Deepen player application orchestration

It restores a settled seam, removes the broadest React leakage, and creates immediate locality and test leverage across loading, scanning, playback failures, and preset persistence.
