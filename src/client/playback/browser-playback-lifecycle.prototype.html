Browser playback lifecycle matrix

Question: can each target-browser outcome be classified without silent-success ambiguity as cancellation, recoverable activation/interruption, analysis-only degradation with a proven audible route, or aggregate-fatal?

Run from the repository root with bun src/client/playback/browser-playback-lifecycle.prototype.html, then open the printed localhost URL.

What did you hear?
1. Autoplay denial and trusted retry

Use a fresh document that auto-runs without any gesture in a fresh profile configured to deny autoplay. The button variant runs after its click's transient activation has expired. Then retry with the trusted button. If denial cannot be forced, record it as unsupported rather than a pass.

2. Pause or load during activation

Starts native resume() and play() together, then issues the competing operation in the same task before awaiting either promise. A fresh aggregate is created automatically.

3. Context close

Observe whether media transport continues while routed output and analyser activity disappear. These cases close the associated context permanently.

4. Source-association failure boundary

Each injection uses a fresh element. “Before association” leaves ordinary media output intact. “After association” throws before an output route exists. “After output” proves whether analyser-only failure can degrade without silencing playback.

5. Background, interruption, and output-device observation

Start observation, then background/foreground the browser, sleep/wake, or change/disconnect an output device. Return and finish. Record what was actually induced in the case note.
